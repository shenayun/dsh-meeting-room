# dsh-meeting-room · 会议室

请几位外部大模型坐到一张桌子上。你说一句、助手回完，他们按顺序接着说。你不叫，他们一个字都不会说。

给 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 用。不依赖别的插件，只读自己的数据目录，装上就是它，卸掉也只有它。

叫「会议室」不叫「圆桌」，是因为这里没有人投票。桌上的人只出观点，判断和决定在你。

## 它怎么工作

你在对话里说一句话，助手回一句。然后桌上开着的那几位挨个说一句，顺序按他们入座先后。

他们看得见前面谁说了什么，也被要求逐条评价，而不是各说各的。这一条是硬要求——不评价别人的发言，那就不叫讨论，叫几个人分别答了一遍。

你随时能把某一位按下去：点他一下，他这一场就不说了，再点一下回来。也可以一键全部闭嘴，那就剩你和助手。想单独听某个人怎么说，点名让他说一句。

开着会议室才算允许他们参与。没开的时候他们不存在于对话里——不注入、不插话、不订阅，不会在你聊天中途冒出来。

## 装

桌面版：侧边栏「插件」→「添加插件」→「安装第三方插件」，填本地目录或者 Git 地址，然后完全重启 DSH。重启以后在「设置 → 会议室」里请人。

装完不用改任何配置文件。数据目录会自动建在 `~/.dsh/meeting-room/`。

## 请一位顾问

打开「设置 → 会议室」，从上往下四步。

第一步，如果下拉里已经有你配置过的模型，可以直接挑一个。地址和模型名会自动填好，只剩密钥要你填。注意 DSH 的配置里存的只是环境变量名，密钥不会跟着过来。

没有的话就自己选提供商：本机网关、DeepSeek、OpenAI、Kimi、智谱，或者自定义。地址会自动填，也可以改。

第二步，填 API 密钥。第三步点「获取模型」——如果能列出多个，从下拉里挑一个；列不出来就直接手填模型名。很多中转站不提供模型列表，这不是出错。

第四步点添加。

只支持 OpenAI 兼容协议，也就是 `/chat/completions`。Anthropic 那套消息格式不一样，暂时不支持。

一把 key 可以加好几个模型。比如同一家的 `glm-5.3` 和 `glm-5.3-flash` 各占一位，方便对比。重名会自动编号，`Glm`、`Glm-2`。

名额上，名单能放 30 个——不同的事请不同的人。但同一场最多 6 个，加上助手正好七个。再多讨论就散了，人自己也听不过来。

## 界面

设置页那一栏管名单和开关。每位顾问前面有个圆点，实心绿表示他这会儿会说话，空心表示不会。右边是改名、移除，还有那个让他闭嘴/开口的按钮。

对话输入框下面有一条，写着「会议室 · N 位顾问」，点开是一块浮层。

浮层默认钉在右边，上下都留了边，不盖顶上的按钮也不压输入框。拖标题栏可以把它拖到任意位置，浮动之后标题栏右边会出现一个 ⌖，点一下贴回去。

上面那截是控制区：开始开会的开关、顾问胶囊、全部闭嘴，都钉着不动。下面是发言区，只有这一块会滚。你贴着底部的时候新内容自动跟上，往上翻看旧内容时它不打扰你。

顾问压成了小胶囊，绿框表示正在说话，点一下切换。鼠标停上去能看到模型名。

发言区默认只看最近几轮。想看更早的点上面那个「加载更早」，一次往前拉十轮——就像翻聊天记录。真要看全部，直接翻 `hall-<日期>.jsonl`，那里面一句都没删过。

## 当跑团桌用

会议室能直接当跑团桌：一个人当主持人（KP），几位顾问各演一个角色。

先开一场，把场景和角色卡存进去：

```
meeting_room action=story \
  scene="雨下了三天，渡口的船工不见了，对岸有一盏灯一直不晃" \
  roles="GLM=老陈，四十七，跑单帮的，身上带着一万二货款；Kimi=小满，二十二，来找失踪的哥哥"
```

之后每次发言，场景会带给所有人，**角色卡只给分到的人**。没分到的会被告知「你是旁听的」，不会抢戏。

判定用 `roll`：`dice=1d20+3 why=划船 dc=15`。点数当场亮出来，桌上所有人都看得见——主持人想偏心也偏不了。

收场不带参数就行：`action=story`。

### 两个必须（不照做角色会乱）

**一、角色卡要用第二人称硬写。** 写成「赵九，三十四岁……」不够，得写「**你就是赵九。别人叫你赵九，你自称赵九。**三十四岁……」。不这么写，几个模型会把自己当成别人，甚至互相叫错名字。

**二、不要一条消息同时问三个人。** 句子里只要出现「你」，人人都以为在说自己。要用 `speak who=<名字>` 一个一个问，按先攻顺序来。

### 能跑到哪一步

先攻、命中判定（1d20+命中 对 AC）、伤害、掉血、非战斗检定（威吓、潜行都行）、敌方回合——都能跑。判定用 `roll`，点数当场亮给所有人看。

**血量用 `track` 记。** 插件不做角色卡，但可以用 `action=track entries="赵九=22/22;阿禾=15/18"` 把数扔进去，之后每次发言自动带上。或者干脆每轮手写在问题里——短局够用，长局容易错。

## 想跑团？

**不用记命令，跟你的助手说一句话就行。**

插件里带了两个现成的短剧本，在 examples 文件夹里。

- **雨里的渡口**：雨夜渡口，船工不见了。不打，全靠说话，三个人各怀心事。二十分钟。
- **山道**：三个人走山路遇上劫道的。能打，带完整的先攻、命中、伤害判定。半小时。

用法：把剧本文件发给助手，然后说——

> 读一下这个剧本，你来当主持人，让我和另外两位当玩家。

剩下的它自己会做：请人上桌、发角色卡、掷骰、按顺序问人、记血。你只管演你的角色、做你的决定。

想自己写剧本也行，照 examples 里的格式：开场、每个角色的卡（AC、HP、命中、伤害），再加一节「主持须知」。最后那节写给助手看，写清「用 story 发牌、track 记血、roll 判定、按顺序一个个问」，它就知道怎么跑。

两个坑先说在前面：角色卡里必须写「你就是某某」，少了这句，几个模型会互相认错人；别一条消息同时问三个人，句子里出现「你」，人人都以为在说自己。

## 它怎么记得住

模型自己没有记忆，每次请求都是全新的。连贯性得由插件喂。

每句话存进 `history/<名字>.json`，最多留五轮。下次请求时，把它自己说过的话以 assistant 回合原样放回去——不是拼成一段文字塞给 user，那是转述，它不认得。

散场的时候把历史清掉，不带到下一场。

## 视角由它自己定

不预设人设，也不分配角色。提示词里只要求三件事：想清楚了就说一句「我从哪个角度看这件事」；没想清楚就别勉强编一个；中途想换个角度可以换，换的时候说一句为什么。

给它们分配视角，等于替它们想好要说什么，剩下的只是表演。

## 数据

全在 `~/.dsh/meeting-room/` 里。

`config.json` 存名单、总闸和网关地址。`current.json` 记这一场谁在、问过几轮、上一轮说了什么。`history/` 是每位顾问自己的对话历史。`hall-<日期>.jsonl` 是流水，谁问的、答的什么、成没成。`meeting-room.log` 是插件自己的日志。

API key 是明文存在这里的，不上传也不外发。这台机器要借给别人之前，记得把 `config.json` 清掉。

## 花的是你们的钱

每说一轮，每位开着的顾问都要调一次接口，按你自己在那些平台的账户计费。插件看不到余额，也管不了额度。

从关到开的时候会拦一次，把这件事说清楚。觉得吵或者想省钱，一键全部闭嘴就停了。

## 会过滤掉什么

会议室只听见你说的话和助手的回复。长期记忆注入、记忆反思任务、运行时快照、交接单、渠道前缀这些系统塞进来的东西会自动跳过。

而且是按轮配对的。如果某一轮整轮都是系统注入，这一轮整个丢掉，不会拿上一轮的问题配这一轮的回答。

## 给助手用的工具

对话里由一个工具管，普通用户不用管它。

`enable` 和 `disable` 开关总闸。`open` 请人入座，不给名字就请开着的那几位。`speak` 就一个问题按顺序各说一次，用 `who` 可以只点一个人。`close` 散场并清历史。`status` 看谁在、刚说过什么。

还有一个 `roll` 用来掷骰：`dice=1d20+3`、`dc=15`、`why=撬锁`。点数、修正、总和、成败一条全亮出来——不是只报「成了」。掷过之后这条也传给桌上的人看，他们知道成败是怎么来的。

`story` 存一场的场景和角色卡，`track` 记几个数——血量、欠账、走到第几步都行：`entries="赵九=22/22;阿禾=15/18"`。记下的东西每次发言都会自动带上，所以报数是读出来的，不是记的。不给参数就是清空。

## 已知限制

只支持 OpenAI 兼容协议。每轮每位顾问都是一次独立请求，真花钱。侧栏是自绘浮层，不是宿主原生面板——原生面板需要宿主自己派发 key，插件开不了。

插件不总结、不投票、不下判决。它只把每个人说的话摊开，结论由用它的助手给，人拍板。

还没有自动化测试。
